# WeatherMonitor

Небольшое веб-приложение для просмотра текущей погоды и прогноза на ближайшие дни. Проект создан в рамках тестового задания и стал практикой работы с внешним API, `HttpClient` и Blazor.

## Возможности

- Просмотр текущей погоды для выбранного местоположения.
- Просмотр почасового прогноза.
- Просмотр прогноза на 3 дня.
- Получение погодных данных через внешний сервис WeatherAPI.
- Отображение информации в адаптивном веб-интерфейсе.

## Технологии

- **C# / .NET 10**
- **Blazor Server** — создание интерактивного веб-интерфейса.
- **HttpClient** — HTTP-запросы к внешнему API.
- **MediatR** — организация обработки запросов.
- **AutoMapper** — преобразование объектов между слоями приложения.
- **xUnit** — модульные тесты.

## Структура решения

- `WeatherMonitor.Application` — логика приложения и обработка запросов.
- `WeatherMonitor.Domain` — модели предметной области.
- `WeatherMonitor.Tests` — автоматические тесты.
- `WeatherMonitor.Web` — веб-интерфейс и интеграция с приложением.
- `Documents` — дополнительные материалы проекта.

## Внешний API

Для получения погодных данных используется [WeatherAPI.com](https://www.weatherapi.com/).

Приложение обращается к API прогноза погоды, передавая координаты местоположения и ключ доступа. Ответ сервиса используется для отображения текущей погоды, почасового прогноза и прогноза на три дня.

Для запуска необходимо зарегистрироваться на WeatherAPI.com и получить API-ключ.

## Запуск проекта

### Требования

- .NET SDK 10
- API-ключ WeatherAPI.com

### 1. Клонирование репозитория

```bash
git clone https://github.com/Alexander-Yurtaev/WeatherMonitor.git
cd WeatherMonitor
```

### 2. Настройка API-ключа

Откройте конфигурацию проекта `WeatherMonitor.Web` и укажите необходимые параметры WeatherAPI:

- API-ключ;
- широту;
- долготу.

Не публикуйте настоящий API-ключ в открытом репозитории. Для локальной разработки рекомендуется использовать User Secrets или переменные окружения.

### 3. Запуск

Из корневой директории решения выполните:

```bash
dotnet restore
dotnet build
dotnet run --project WeatherMonitor.Web
```

После запуска откройте адрес, указанный в выводе приложения.

## Тестирование

В проекте предусмотрены автоматические тесты для проверки отдельных компонентов и логики приложения.

Запуск тестов из корневой директории:

```bash

```
